# Policy Assistant

A **RAG (Retrieval-Augmented Generation) document assistant** that answers questions about a set of policy documents — grounded in the documents, with **source citations**, honest enough to say *"I don't know"* when the answer isn't there, and backed by an **evaluation suite** that measures how well it actually works.

Built with Claude, a local embedding model, and a vector database. It ingests your documents, retrieves the most relevant passages for a question, and has Claude answer from those passages only.

## Why it exists

Large language models don't know your organisation's internal documents and will confidently make things up when asked. This assistant fixes that by retrieving the relevant policy text first and instructing the model to answer only from it — the standard pattern for trustworthy AI over private / regulated document sets.

## How it works

```
question ─▶ embed ─▶ search vector DB ─▶ top chunks ─▶ prompt Claude ─▶ cited answer
```

| File | Role |
|------|------|
| `documents/` | The knowledge base — drop `.pdf`, `.txt`, or `.md` files here. |
| `ingest.py` | Loads documents, chunks them, embeds each chunk, stores them in the vector DB. |
| `core.py` | Shared config, embedding, chunking, and document loading. |
| `rag.py` | The RAG engine (retrieve → augment → generate) + a terminal chat. |
| `app.py` | A Streamlit web chat UI on top of the engine. |
| `evaluate.py` | Measures retrieval hit-rate and answer correctness on a test set. |

Embeddings run locally via `fastembed` (no embedding API key needed); retrieval uses a local on-disk **Qdrant** vector database; answers are generated by **Claude**.

## Setup

Requires [uv](https://docs.astral.sh/uv/) and an [Anthropic API key](https://console.anthropic.com).

```bash
uv sync                       # install dependencies
# copy .env.example to .env and paste your API key
uv run ingest.py              # load the documents into the vector DB
```

## Usage

**Web app (recommended):**
```bash
uv run streamlit run app.py   # opens a chat UI at http://localhost:8501
```

**Terminal chat:**
```bash
uv run rag.py
```

Example:

```
You: how many volunteer days do I get, and do I need approval?
Assistant: Employees may take up to 3 days of paid volunteer leave per year,
and it must be approved by your manager. [leave-and-expenses-policy.md]
```

## Evaluation

RAG systems fail quietly — a wrong answer looks just like a right one. So this project **measures** itself:

```bash
uv run evaluate.py
```

It runs a set of test questions and reports two metrics:

- **Retrieval hit-rate** — did it fetch the correct source document?
- **Answer pass-rate** — is the generated answer correct? (graded by an LLM-as-judge against reference answers)

One test case has no answer in the documents, verifying the assistant **abstains** instead of hallucinating. Extend `TEST_CASES` in `evaluate.py` as you add documents.

## Using your own documents

Replace the sample files in `documents/` with your own `.pdf` / `.txt` / `.md` files and run `uv run ingest.py` again. (Stop the app and terminal chat first — the local vector database is opened by one process at a time.)

## Notes

- Answers are grounded in the supplied documents and cite their source; the assistant declines when the answer isn't present.
- The sample documents included here are fictional, for demonstration.
